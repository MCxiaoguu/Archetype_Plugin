- Plugin-driven test runs / instruction serving: no endpoint returns persona-enriched instruction sets. Building blocks that exist: features CRUD carries associatedPersonaPoolIds linking features->persona pools; Persona.user_persona_pools; Auth0 Device Flow at /api/oauth/* (routes_oauth.py) is ready-made CLI/plugin auth issuing Bearer tokens valid on every @require_auth route; Archetype_Plugins repo (cwd) already has an MCP login wizard.
- Plugin result ingestion into MongoDB: no HTTP write path. session_log writes (start_session_log/log_step/finalize_session_log in simulation_core/log_result.py) and event publishes (publish_test_update/publish_fleet_event in services/event_bus.py) are in-process only, called from Celery tasks (tasks/notte_tasks.py, tasks/uat_tasks.py, tasks/watchdog.py) and simulation_core/notte_runner.py. An external Claude Code plugin cannot POST progress events or session results today; the only HTTP mutations are POST /api/test_engine/test/<id>/complete (status flip) and POST /api/validation-tests (create).
- routes_feedback is generation/read-only; no endpoint accepts externally supplied feedback documents (the 'generate' POST ignores its request body and just rebuilds the summary).
- GET /api/validation-tests/<id>/reaction-results is effectively dead: it calls feedback_service.get_reaction_results which unconditionally raises RuntimeError (feedback_service.py:25-31), so the deprecated route 500s.
- GET /api/progress/<user_id> allows any authenticated user to read any user's wizard progress (routes_progress.py:41 'in real deployments, protect with admin role check').
- infrastructure/MCP/posthog_mcp.py is an unimplemented TODO-checklist stub; POSTHOG_API_KEY documented in config.py:66 but no PostHog capture (and no PostHog session-recording fetch) is implemented.
- Feedback GET response is thinner than its documented contract: routes_feedback.py:27-43 docstring promises consensusScore/averageRanking/topConcerns/commonThemes top-level keys; handler returns only {testId, feedback}.
- POST /api/validation-tests creates the test doc but does not enqueue execution — run start is a separate call (POST /api/test_engine/start_session, routes_agent.py:45); a plugin-driven runner must replicate this two-step flow or get a new trigger endpoint.

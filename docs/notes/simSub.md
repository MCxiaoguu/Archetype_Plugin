## gaps
- No session-replay ingestion exists anywhere (grep for rrweb/session_replay/replay_ingest across Archetype_Core returns nothing). The only 'replay' is validation_monitor_replay.py, which replays *agent* fleet events from session_log, not real-user session recordings.
- No persona-from-replay generation. Personas come from persona pools (Persona.user_personas) generated by the persona module; there is no pipeline that derives a persona from recorded user behavior.
- stream_replay (services/validation_monitor_replay.py:285) is fully implemented but has NO route wired to it — the docstring-promised GET /validation-tests/<id>/events endpoint does not exist in any blueprint. Must be added before the frontend/plugin can use durable replay.
- No plugin result-ingestion endpoint. There is no POST endpoint that accepts session steps/results from an external actor; session_log is only written server-side by Celery tasks via log_result.py. A plugin-based actor needs either (a) new ingestion routes that call start_session_log/log_step/finalize_session_log + run_post_session_analytics + finalize_test_results, or (b) a new Celery-free path replicating notte_tasks.py:288-359.
- The plugin skills (Archetype_Plugins/skills/validate-feature, check-run-status, agents/feature-validator.md) call POST/GET {ARCHETYPE_PORTAL_URL}/api/feature-validation/runs[/{run_id}] and reference ARCHETYPE_API_KEY — none of these endpoints exist in the backend (grep 'feature-validation' returns nothing) and the backend uses Auth0 JWT Bearer, not an API key. Skills are aspirational specs, not working integrations.
- No persona-enriched instruction-set endpoint for a plugin. seed_card rendering (persona/seed.py:render_seed_card + persona/registry.py:contract_from_persona) and goal/persona_need assembly happen only inside the Celery task (notte_tasks.py:171-192); nothing serves that text over HTTP.
- finalize_test_results completion detection is chord-coupled: for a plugin actor not using Celery, the auto-finalize on 'all sessions finished' path exists only in session_result_update (agent_simulation_service.py:530-538, counts session_log status=='finished'), while log_result.finalize_session_log writes status 'success'/'quit' — status-string mismatch ('finished' vs 'success') means that fallback path will not fire for logs written via finalize_session_log; a plugin path must call finalize_test_results explicitly or reconcile statuses.
- POST /api/test_engine/start_session has no @require_auth decorator (routes_agent.py:45-46) — auth model inconsistency to resolve before exposing plugin-driven runs.
- Fleet events for live monitor (session_started/narration_line/transition) are published only by NotteSessionRunner/notte_tasks; a plugin actor must publish the same shapes via publish_fleet_event (or rely solely on post-hoc replay once the /events route exists) to appear in the monitor UI.
- BTW ask (dispatch_btw_question) reads sess_doc.seed_card from session_log (validation_monitor_service.py:44) but nothing currently writes seed_card into session_log docs — likely always empty; a new actor writing seed_card there would make BTW answers persona-grounded.
- stage_count_delta bucket counts are in-process per-runner (notte_runner.py:516-533) — a multi-process plugin actor fleet would produce inconsistent bucket_count values across sessions.

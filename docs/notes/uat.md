## gaps
- No session-replay ingestion endpoint anywhere. services/validation_monitor_replay.py only re-emits stored validation-run events from Mongo for the monitor UI (src:"replay"), not user session-replay capture.
- No persona-generation-from-replay. Personas live in routes_persona (/api/persona) and services/persona_service.py; the UAT/validation bootstrap only *suggests* persona pool IDs via LLM (suggested_persona_pool_ids) and validates them against a provided list (uat_bootstrap.py:87-92) — but routes_bootstrap.py:88-93 never passes persona_pools (or features to validation mode), so that parameter is dead in the live path.
- Test cases carry persona_ids and persona_credentials fields end-to-end (Mongo + both transforms) but the runner/Celery task never reads them — only the single run-level credentials dict from POST /run is used for [session_email]/[session_pw] substitution (runner.py:192-199, uat_tasks.py:36-39). Persona-enriched instruction sets = new work.
- No plugin-facing instruction-set endpoint: no route serves a test plan/instruction set to an external agent; GET /api/uat/tests/<id> requires the browser-user JWT. OAuth device flow for plugin auth already exists (POST /api/oauth/device/code, /device/token, /validate-token — api/routes_oauth.py) and the plugin caches tokens in ${CLAUDE_PLUGIN_DATA}/auth.json.
- No plugin result-ingestion endpoint. Results are only written internally by the Celery task via uat_service.save_case_result / append_defect / finalize_results / mark_failed (uat_service.py:143-201) — these helpers are directly reusable for an ingestion route.
- Plugin skills already reference endpoints that DO NOT exist in the backend: POST {ARCHETYPE_PORTAL_URL}/api/feature-validation/runs (Archetype_Plugins/skills/validate-feature/SKILL.md:19) and GET /api/feature-validation/runs/{run_id} (skills/check-run-status/SKILL.md:13). grep of Archetype_Backend/api/*.py finds no "feature-validation" route — this contract must be built.
- Only browser-agent execution exists (Notte cloud sessions driven by Gemini action-mapper); there is no notion of a Claude-Code-plugin-driven test run, run records separate from the uat_tests doc (no runs collection — results are embedded in the test doc, one active run at a time gated by run_epoch), or per-run history.
- Bootstrap generation is chat-only (POST /api/bootstrap with messages[]); no programmatic generate-instruction-set-from-persona/replay endpoint.
- Screenshots are stored inline as base64 in the Mongo doc (results.step_logs[].screenshot_b64 and results.screenshots) — a size risk to note if plugin runs ingest many artifacts (16MB Mongo doc limit).
